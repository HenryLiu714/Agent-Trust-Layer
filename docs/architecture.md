# Architecture

irimi is a local MITM proxy that sits between an agent and the services it talks to. Reads are
forwarded to the real service, writes are answered locally, and (from Phase 2) reads after writes
see those writes. This document is the map of the code: what each module is for, how a request
moves through them, and which rules the tests hold the layout to.

## One request, end to end

mitmproxy calls `IrimiAddon` (`src/irimi/engine/mitm.py`) once per flow. The addon only turns
flows into `Request`s and `Response`s and carries plans onto them; what irimi decides and records
is `session.ShadowSession`'s, which every engine drives, in this order. Nothing
through the listener skips them: mitmproxy's raw TCP relay is off (`rawtcp=False`), so a tunnel
whose first bytes mitmproxy would not call HTTP (a method like `M-SEARCH`, or a first segment of
under three bytes) is parsed as HTTP and decided like any request, bytes that are not HTTP fail
there, and a connection a live `101` upgraded to anything but a WebSocket is closed. None of them
is relayed, and none leaves a record (#75).

1. **`request`** - `wire.parse` normalises the wire request, and `ingress.admit` says what it is
   to irimi: a request addressed to the listener itself whose path starts with `/_irimi/` is the
   control endpoint (#73), which `control.ControlEndpoint` answers in the hook, so it is never
   forwarded, decided or recorded as an exchange; a request on the listener otherwise came in as
   `/<host>/<path>` and is rewritten upstream; one irimi cannot route or rewrite is a `Refusal`,
   answered by `ShadowSession.refuse`. `admit` reads the run id from `Irimi-Run` and takes it and
   any agent-sent `Irimi-Rewrote` off the request, and the addon takes them off the flow, so
   neither leaves irimi (#67). Then `ShadowSession.plan`, on a worker thread, builds the `Plan`:
   `classify.classify` says what the request is (`read`, `write`, `llm`, `telemetry`,
   `unknown`), `delegation.delegate` resolves its answer target once, a read the overlay can
   translate (a cursor naming a minted id, #43) is translated unless it is delegated, and is what
   the policy is asked and what the trace records, whoever answers it (#82). The `AnswerPolicy`
   decides `Forward`, `Delegate` or `Respond` (`services`: the route's L1 fixture when its map
   names one, the L0 echo otherwise); a `Respond` is stamped as it is planned, and a target is
   probed and refused on the worker thread. The addon carries the plan onto the flow and keeps it
   in the flow's metadata. **Nothing in this hook may raise**: an exception here makes mitmproxy
   forward the flow untouched, so the hook runs under one guard and fails closed with a `502`
   flagged `decision-failed`, and so does turning the answer into mitmproxy's, since a replay's
   answer was read off disk (#82); the precondition reads that answer made are still recorded.
2. **`responseheaders`** - stamps `Irimi-Answered-By` on a live or delegated answer before the
   headers go out, and streams a `text/event-stream` answer through a `StreamCapture`, which hands
   each chunk on unchanged and keeps a copy for the trace (#71).
3. **`response`** - `ShadowSession.complete`: every unstreamed read's body goes past
   `services.observe_read` first, which is how a service learns the real values its fakes have to
   sort against (Slack's `ts`); a service with no observer is a no-op. Then, for a live,
   unstreamed read, the `Overlay` gets a chance to rewrite the body from the write log. It builds
   the `Exchange`, writes join the write log, `wire.stamp` stamps a forwarded answer, and
   `ShadowSession.record` hands it to the `TraceStore` - which keeps a telemetry exchange only as
   a count (#70) - and reports it to the CLI.
4. **`error`** - `ShadowSession.fail`: a lost upstream or an unreachable target is annotated with the right flag and
   recorded with no response, so a failed write is never silently dropped from the trace. A
   stream that fails after its headers went out keeps the complete lines its `StreamCapture` copied,
   flagged `stream-truncated` (#71).

Every body a hook records is decoded by `engine.decoding.decode_body`, which never raises and
never decodes past `limits.MAX_DECODED_BODY` (#94): each codec runs incrementally and stops at
the cap, so a small compressed bomb costs a hook at most twice the cap in memory. A body cut there
is never decoded or redacted whole, so it is recorded empty and flagged, as the store records any
body past the same bound; a stream keeps its first `limits.MAX_STORED_BODY` bytes of whole lines, as any stream that
is not whole does. Such a read is never overlaid, so the agent gets the service's bytes unchanged,
and one the run has a write for is `overlay: partial`, as a body the overlay cannot parse is.
Nothing is answered from the start of a body: a write whose request body was cut fails closed
like a decision that raised (`502`, `decision-failed`, `body-truncated`), a live kind is forwarded
with the agent's own bytes, and the control endpoint refuses a cut body `413`.

## Layers

Every module lives in exactly one layer and may import only from layers above it in this table
(lower layers never import higher ones). `tests/test_import_boundary.py` enforces this, and also
that `mitmproxy` is imported in `engine/mitm.py` and nowhere else. Add a module and the test asks
you to place it. A package is one layer, except `replay/`, whose modules sit in three layers and
are placed one by one; its `__init__` imports nothing.

| Layer | Modules | Responsibility |
| --- | --- | --- |
| 0 | `exchange` | The wire vocabulary: `Request`, `Response`, `Exchange`, the kinds, the `answered_by` values and every flag, and `is_authored_write`, the one statement of which writes enter a run's write log - the summary files an overlaid read by the same rule (#48). An exchange's `precondition` is one `Precondition` value - the check's outcome, the rejection code, and the `currency` its read found on the object the write names, the only thing besides the request that may denominate an amount in the summary (#60) - which the trace format keeps as three flat keys; `WriteOutcome` is that value with the webhooks a faked write would fire, as the policy decides it. It also holds the helpers every layer reads a message with: `header_value` / `Request.header`, `without_header`, `Request.path_and_query` and `media_type`. Every flag is a member of `Flag`, a `StrEnum`. The write-set predicates sit together, each contrasted with the others: `is_authored_write` (the write log), `is_intercepted` (the summary's writes), `is_faked`, `refused_by_irimi`, `failed_target`, and `fake_ran` for a write tool. An exchange's `started_at` and `ended_at` are wall-clock seconds, read by the engine: the request hook's first parse to the hook that finishes the flow, or an engine-issued read's `Reader` call, and never ending before they start (#68). A streamed response's `stream_chunks` split its recorded body into the chunks the agent was sent, and `clip_chunks` cuts them where a body is cut (#71). |

| 1 | `servicemap/` | The service maps. `model` is the dataclasses, the host index, route matching and the target precedence; `rules` is the validation (THE SCOPE RULE lives here); `loader` turns YAML, the overrides file and the `--target` flags into a `MapIndex`. |
| 1 | `bodies` | The one never-raising parser for a request's fields (`reflect`, Stripe's bracketed form encoding included) and a body's JSON object (`json_object`, capped at `limits.MAX_BODY_BYTES` unless the caller says otherwise). |
| 1 | `trace` | Trace format v2 (#68, #82): the records a stored run is made of - `RunRecord`, `Trigger`, `ErrorInfo`, `ToolCall`, `TelemetrySeen`, `BodyRef` - and pure JSON codecs for them and for `Exchange`, with no I/O. Bodies never go inline: the exchange codec hands them to the caller's `put_body` / `get_body`. A decoder raises only `TraceFormatError` (whatever the caller's `get_body` raises aside), refuses a newer `SCHEMA_VERSION` and ignores fields it does not know; `docs/trace-format.md` says what a later field or vocabulary value costs. Also `mode_for`, the one rule for a run's mode: `replay` when the engine answers from a stored run, `shadow` otherwise (#82). Also `is_valid_run_id`, the path-traversal guard a run id passes before it may name a run - and so a directory. Also what a replay never hands back as a tool's outcome, which the recording and the SDK both read (#83): `holds_description`, a captured value holding `REPR_KEY` or `TRUNCATED_KEY`, and `STOPPED_ERROR_TYPES`, what a call stopped from outside records. Also `StoredRun`, a run's record and events as the store reads them back; `RunRecord.process`, `.sdk` and `.header`, the only constructors of a record, each setting `mode` from `replay_of`, which the store checks rather than sets; `RunEnd`, how a run ended, `None` until it has; `Trigger.argv`, a process run's command line, which `run.json` keeps as `args: {"argv": [...]}`; `new_run_id` and `new_tool_call_id`, the one place ids are minted; and the public `read_*` field readers, which `protocol.control` decodes posted bodies with. `docs/trace-format.md` is the reference, and its example is decoded by the tests. |
| 2 | `protocol/` | The contract between the engine and the SDK, which both import and never each other: `headers` (every `Irimi-` header name), `env` (every variable `irimi shadow` and `irimi replay` give their child, and `PROXY_ENVS`), `control` (the control endpoint's prefix and routes, `RunAction`, `PROTOCOL_VERSION`, and the posted bodies `RunStart`, a run's end and `RecordedOutcome`, each with free-function codecs built on `trace`'s readers) and `replay_files` (`CallOutcome`, what a replay's child writes, and `ReplayResult`, what `irimi replay --result-file` writes, with their codecs). |
| 3 | `classify` | What a request is: `Classification`, `classify` by the maps and the RFC fallback, and the scope rule's decision half. |
| 3 | `wire` | irimi's side of the wire: `parse`, `attribute_run` (an `Irimi-Run` value `trace.is_valid_run_id` refuses is treated as absent), `stamp`, which puts `Irimi-Answered-By` on every answer irimi decided, and `irimi_error`, the one JSON error body. |
| 3 | `redact` | Redaction before anything reaches disk (#69), and the one statement of what of each event and run record goes there: `for_disk` is the copy of an exchange, tool call or telemetry line the trace store writes, `run_for_disk` the copy of a run's record, `redact_error` an error redacted whole and only then cut to a label, and `redact_request` a request as the store would write it, which a replay keys a live request by. `redact_exchange` returns the copy of an exchange, and `redact_json` the copy of a trigger's or tool call's JSON; none raises, and a part that cannot be redacted is stored as `<redaction-failed>` and flagged `redaction-failed`. A secret becomes `placeholder(key, value)`, an HMAC under this install's `load_key` key, so one secret is always one placeholder; the shapes it finds in text are `secret_shapes.SECRET_SHAPE`'s (#179). It is also the one statement of which headers are credentials (`is_credential_header`), which `delegation` strips from a target's request by the same rule, and of where a line ends (`complete_lines`), to which the engine trims a stream that is not whole so that redaction can read every line of it (#71). `docs/trace-format.md`, "Redaction", lists every rule. |
| 3 | `sdk/` | The SDK an agent imports (#74), beside `wire` rather than above the engine because it runs in the agent's process, not irimi's. `api` is `@sdk.trigger` and `sdk.run()`; `context` is the run's id in a context variable (`current_run_id`, `propagate`); `runs.RunScope` is the one lifecycle both share - join a current run, or, in a replay's child, adopt the replay's run and post nothing (#84), or capture the trigger, mint an id, post the start, run, post the end, reset. A trigger makes a fresh `RunScope` per call; one `sdk.run` object may be entered again, so it keeps one scope per entry, per context; `capture` turns a trigger's arguments into JSON and says whether they are replayable (the table in `docs/trace-format.md`), and `revive` turns that JSON back into values, or says `NotReplayable` (#83); `client.ControlClient` posts to `IRIMI_CONTROL` over stdlib urllib, never through the proxy, and never raises, logging one warning per kind of failure; `instrumentation.instrument` patches `http.client.HTTPConnection.putrequest` and, when httpx is installed, httpx's two transports, once per process on the first run, so a run's request carries `Irimi-Run` only when its connection goes to irimi's listener (the host and port `IRIMI_CONTROL` or a proxy variable names), and never the SDK's own posts (`unlabelled`) (#75); `tools.tool` is `@sdk.tool`, a read or write the proxy cannot see: an active write runs only the stand-in it names, every active call is posted as a `ToolCall` to its run (the current one, else `IRIMI_RUN`, else `unattributed`), mistakes are TypeErrors at decoration (THE SCOPE RULE's shape), and `_chosen` is the one dispatch (#76). In a replay (`context.replay_run_id`, from `IRIMI_REPLAY_RUN`) a read tool first asks the control endpoint for its recorded outcome (`_replay_answer`, `ControlClient.recorded`, a `protocol.control.RecordedOutcome`; off the event loop for an `async def`, and only then), and a hit runs nothing: the result is revived, or the recorded error raised as `errors.RecordedToolError`, a subclass of the builtin it names when it names one, and the call is recorded `ran: recording`; a miss, a failed lookup or a result that does not revive runs the real function. A write runs its stand-in in a replay too. `errors.error_info` is what a run or a tool call records an exception as, so a recorded error is recorded as the recorded type (#83). `context.replay_run_id` trusts `IRIMI_REPLAY_RUN` only when it names the child's `IRIMI_RUN` too, as irimi sets both, so a stale export in a serve agent's environment adopts nothing (#84). `api.resolve` is `api.entrypoint`'s inverse, the function a `module:qualname` names, imported, a plain method refused, since a run records no instance; `capture.call_arguments` undoes `capture_call`'s binding; `replay_child` is the child `irimi replay` starts to call a trigger with its revived args, which says how the call ended in a `CallOutcome` file and exits `CANNOT_CALL` for a call it could not make; `replays` is `sdk.replay()`, `irimi replay` run by its one seam, `_run_irimi` (a subprocess, unless a harness swaps it), with the args in a file, and `ReplayResult`, from `protocol.replay_files`, whose codec reads what `--result-file` writes (#84). Inert while `IRIMI_ENGINE_ACTIVE` is not `1` (`context.active`). Imports only the stdlib, `protocol` (the control routes and bodies, the header and environment variable names), `trace`, `limits`, `opener`, `secret_shapes` and the package's `__version__`, never mitmproxy, so it can later ship on its own. |
| 4 | `delegation` | Answer targets (design D20): which target answers a request, where it is sent, what it may never be, which headers it may not carry (`redact.is_credential_header`, re-exported: the rule disk shares, #69). |
| 4 | `services/` | What irimi knows about each service: one `model.Service` spec per service, held by name in `REGISTRY`. `stripe/` and `slack/` are packages whose `__init__` is the spec; their maps and fixtures stay in `irimi/maps/` and `irimi/fixtures/`. A spec names the operations its code keys on, how its faked writes are answered (`Answer`: a body builder, and the operations answered with a literal non-JSON body), what a forwarded read teaches it (`observe_read`), its read effects and cursor rewrite, its preconditions by `precondition:` name, its idempotency, the headers that scope its state and the credential headers a precondition read copies. A field left unset is the generic behaviour, and a service with no spec gets the generic behaviour throughout. `__init__` is the registry; `check`, which the composition root runs when the maps load and which refuses maps that lack a service or an operation a spec keys on, or a route whose `precondition:` or `fixture:` names nothing; `scope_of`; and the answer dispatch: `fake_response` builds and serializes a faked write's body, `fake_level` says what level a route's write is answered at without building one, `fake_rejection` carries an L3 rejection's modeled error body at that level (there is no `fake-L3`), and `observe_read` is the one seam where a forwarded read's body teaches the faker something (a Slack `ts` a minted one must sort after). `generic` is the echo and fixture body any service gets: reflected fields (read with `bodies.reflect`), the ids a route mints (`ids:`, a prefix, `{format: int}` or `{format: uuid}`), L1 as the route's fixture with the request's own fields written over it (`reflect_over`), and the fixture files themselves, read from `irimi/fixtures/<service>.json`, cached, and never raising. Each service package has `answers` (Stripe's adds the fields every Stripe object carries: `created`, `object`, `livemode`; Slack's is its envelopes, `SLACK_ENVELOPES`, else a default `{ok, channel, ts}`, whose `optional:` fields are dropped when the caller posted none, and its `ts` sequence, a `TsClock` each `ShadowPolicy` owns), `effects` (what a faked write does to a later live read, as plain functions over plain data; an effect may also answer a read outright, status and all, with `Applied.status`, for a read of an object this run minted) and `preconditions` (each `Check` says which one real read it needs and what the answer, with the run's writes applied, makes of the write; `Check.currency` names the code the document denominates amounts in; a verdict is rejected, passed, or `NOT_EVALUABLE` for a document it cannot read). `model` is the vocabulary: `Read` / `Write` / `Applied` / `Rewritten`, `Proposal` / `Probe` / `Rejection` / `NotEvaluable` / `Check`, `Idempotency`, `Answer` and `Service`. Pure but for reading the fixture files: no clock in the effects, no minting outside the answers, so a replay runs the same functions over a recording. |
| 4 | `ingress` | How a request reached irimi, and what irimi makes of it before deciding: `admit` returns an `Admitted` request (rewritten upstream when it came by base URL, `Irimi-Run` read and irimi's own headers taken off), a `ControlCall`, or a `Refusal` for a request irimi cannot route or rewrite. `detect_door` takes the address the connection arrived on, so a request naming that address, or a name resolving to it, is the listener's own whatever it is bound to (#77); `rewrite_reverse` is the base-URL rewrite, loopback clients only, to the allow-list of exact hosts. Pure. |
| 4 | `reader` | `Reader`, `NoReader`, `UpstreamReader`: the one real read L3 issues, and shadow mode's reader over stdlib urllib (#45), which names no proxy and follows no redirect, as mitmproxy's own forwarding does: it dials the host the classifier saw, and a 3xx is the answer, which the policy takes as `not_evaluable` (#85). `answered_as` is what a reader's reads are recorded as: the `answered_by`, `flags` and `miss_flags` the `Reader` protocol declares, `live` and none by default, which a replay's `RecordingReader` overrides (#82). |
| 5 | `writelog` | The run's faked writes, decoded out of the trace into `services.Write`s, in the scope a read is asking about. `apply` is the one path from the write log to a read's document, shared by the overlay, which applies the writes to a live read, and the precondition check, which checks a new write against them (#45); `scoped_writes` / `read_of` are its parts, and `Translation` is a read the overlay translated. Pure, but for `WriteLog`, which keeps each run's faked writes apart, by run id, and drops a run's when the store reports the run ended: a run never sees another run's writes, and requests no run names share one log of their own. |
| 5 | `idempotency` | The run's answers to writes that carried an idempotency key, so an agent's retry with the same key is one write and not two (#46). A key held with different parameters is the service's own `idempotency_error`, and "the same write" is compared as the whole request - method, path, query and the posted fields the route does not list in `compare_ignores:` - because a key names one write and not one route, and `payment_intents.cancel` posts nothing at all. In memory, a run's keys dropped as it ends, lock-guarded because the decision runs on a worker thread, and pure enough for a replay to keep the same promise over a recording (#82). `FirstAnswer` carries the first answer's `Precondition`, its currency included, so a retried write's exchange and the first one's agree about what that single write was denominated in (#60). |
| 5 | `replay/index` | A stored run as a replay answers from it (#82), in the `replay/` package, whose modules are placed one by one. `ReplayIndex.from_events` takes a `StoredRun`'s events and keeps the agent's exchanges in order, by key, apart from the engine's precondition reads. "The same request" is its kind, method, host, path, query pairs sorted by name (a repeated name's values kept in their order) and the service's scope headers (`services.scope_of`, a Stripe account), with the body `bodies.reflect` reads less the route's `compare_ignores:` fields, as canonical JSON, and no other header; an llm call's JSON body less its route's `compare_ignores:` (who asked: `metadata`, `user`, `stream`, `stream_options`, `prompt_cache_key` in the shipped maps) and every `cache_control`; and a live request is redacted with the store's key first, as the recording was, so a secret matches its placeholder (#69). `answer_for` hands each recorded exchange out once, an llm call's beside whether its recorded call asked to stream and a write's beside its standing in the run's idempotency store (`idempotent-replay`, `idempotency-conflict` or neither, #46), and calls one it cannot serve (cut, a refusal of irimi's, a lost upstream, a target's, a write irimi did not fake, a status outside 200-599, a header the engine could not send) a miss in its place. A read, or a write L3 checked, recorded after a recorded write the replay has not made, or reached once the replay has diverged, shows a world the replay is not in, so it is a miss and the replay diverges. `tool_answer_for` does the same for a read tool the SDK asks about (#83): by name and args redacted with the store's key, as canonical JSON, in order. A recorded call with no outcome to give - a result or an error message redaction could not read, a result holding a description (`trace.holds_description`), or a call stopped from outside (`trace.STOPPED_ERROR_TYPES`) - is a miss in its place that uses up nothing else, so the body that then runs is answered from the recording. An answered call uses up the exchanges recorded within its span, its body's HTTP, which the replay never makes, and the read tool calls within it that a later call of the same name and args would otherwise take, the tools its body called (a span cannot tell those from another task's, which is left to answer its own call); it is placed under the world rule where its body began, and one recorded after a write the replay has not made misses without diverging, since its body then runs. A write tool call is never kept, since with no tool overlay (#119) no recorded read shows one. The replay's state is here and only here: what has answered, and whether the replay has diverged (`diverge`, `diverged`), engine-wide, since a replay is one run. `made_within` and `nested_in` say whether an exchange or a tool call was made within a read tool's span, which `replay/report` counts by too. `RecordingReader` is a `reader.Reader` over the recording's precondition reads, never used up, whose reads are recorded `recording` and `from-recording`: a replay never checks a precondition against live state. Pure but for one lock. |
| 6 | `preconditions` | The precondition check (L3, #45): `check` builds the one real read a route's `precondition:` needs from the map's route, refuses any the maps do not call a read, makes it through `reader.Reader`, applies the run's writes to its document with `writelog.apply`, and asks the service's `Check` for a verdict. It returns a `Checked`: the `Precondition` (outcome, rejection code, currency), the read it made, marked `issued_by: engine`, and the service's rejection when there is one. It never raises: a check it could not finish is `not_evaluable`. |
| 7 | `policy` | `AnswerPolicy` and `ShadowPolicy`: the decision as a table, and only the decision. A decision is `Forward`, `Delegate` or `Respond`, each carrying only its own data, returned in a `Decided` with the flags it adds and the reads it issued. The answer target is resolved by the caller and handed in. Part of deciding a mapped write is `preconditions.check`, whose read the policy returns for the engine to record. Also the idempotency lookup (#46), which sits between the live-kind check and L3 and finds a write's slot with `idempotency.slot_for`: a retry with a key this run has already answered returns the first answer and issues no precondition read, and a key reused with different parameters is answered with the service's own `idempotency_error`. The accepted local fake, the one path left after all of those, is the only `Respond` whose `WriteOutcome` carries its route's `fires:` as `would_fire` (#47). `recorded_tool_call` is a read tool's answer from a replay's recording (#83), `ShadowPolicy`'s always None. The idempotency helpers (`idempotency_standing`, `remember_answer`) are public for `replay/policy`, whose policy shares the store with the shadow policy it holds. |
| 6 | `overlay` | The `Overlay` seam and `ServiceOverlay`, which applies `services`' effect tables to a live read (through `writelog.apply`) and translates a cursor naming a minted id before the read is forwarded. It is handed the engine's `Classification` of the read and keeps no index of its own. `NoOverlay` stays, for tests and for a mode with no overlay. The module's header lists the two hazards every overlay must respect. It may also replace a response's STATUS, which only a read of a minted object ever asks for: Stripe answers `GET /v1/refunds/{minted}` with a 404 and Slack answers a minted thread with `thread_not_found` at 200, and both are answered from the write log instead (#52). |
| 6 | `store` | The trace store (#70), a package that is one layer: `store` holds the seam and `StoreStats`, `store.layout` where each file lives (`StoreLayout`, `names_a_run_dir`, reading a run.json, resuming a `seq`), `store.writer` the writer (`DirectoryStore`, `RunAttribution`), `store.reader` the reader (`StoreReader`, `RunNotFound`) and `store.lock` the serve lock (`ServeLock`, `StoreLocked`). `TraceStore` is the seam: `start_run`, `record`, `record_tool_call`, `end_run`, `stats`, `close`, none of which may raise. `DirectoryStore` writes the layout in `docs/trace-format.md`: each public method only enqueues onto a bounded queue and returns, and one daemon writer thread redacts (`redact.for_disk`, `redact.run_for_disk`), hashes and writes, so a hook never blocks on disk. A full queue or a failed write drops the event and counts it on the store (`stats()`) and on its run (`dropped_events`), and a start for a run that has already ended is dropped, counted on the store alone, and changes nothing (#97). The queue is bounded in items and in bytes - an exchange's bodies, and a tool call (#76) and a run's start (#99) as their whole JSON, while an end costs no bytes, its error waiting cut outside secrets to `MAX_QUEUED_ERROR` and redacted whole before it is cut to a label (#179) - a body too big to redact is never queued, and a run's state is forgotten when it ends, so a `serve` running for weeks holds only the runs still open (one whose end never arrives, and a `header` run, which never ends, are held until `close()`). ## The seams

Four protocols are where later phases plug in, and the reason the rest of the code can be tested
without a proxy:

- **`engine.Engine`** - run, shutdown, wait for the listener. `runner.start_engine` drives it on a
  background thread; `cli` never touches mitmproxy directly.
- **`policy.AnswerPolicy`** - given a `Request`, its `Classification`, its answer target and
  (defaulted, #45) the run's write log and id, return a `Decided`: `Forward`, `Delegate`, or
  `Respond` with this response. It stays synchronous; the session calls it on a worker thread.
  `ShadowPolicy` takes a
  `reader.Reader` for the L3 precondition read; built without one it does no L3 at all and records
  `precondition: None`. Replay is a new policy, not a new branch (#82): `ReplayPolicy` answers from
  a recording and hands the rest to a `ShadowPolicy` whose reader is that recording. A replay is
  one run, so only `irimi replay` replays, and serve mode cannot (#84).
- **`overlay.Overlay`** - given the write log, a read's classification and request and the upstream response, return
  an `Overlaid`: the response the agent should see, and how much of the write log that read could
  express. Its request side, `rewrite`, translates a read before it is forwarded. Both are pure
  functions of their arguments, and the engine asks `rewrite` of a read before the policy decides,
  so the policy and the trace see the read as irimi would ask it (#82).
- **`store.TraceStore`** - where a run's record, its exchanges and its tool calls go (#70).
  `irimi shadow` starts its process run before spawning the child and ends it with the child's
  exit code; an exchange whose run has no start creates a `header` run. No method may raise or
  block: `record` is called from mitmproxy's hooks. `DirectoryStore` is the only real store, and
  a replay reads what it wrote with `StoreReader`; a store a replay writes keeps only starts whose
  record names that replay (`mode: replay`, `replay_of`, set by the record's constructor),
  makes each header run that replay's, and writes no run it did not make, the run it replays
  included. An SDK run's start, end
  and tool calls reach it through the control endpoint (#73), never from the agent's process
  directly.

## Rules the code holds itself to

Each of these has been a real bug here; each is now enforced by a test, and most are enforced
twice - once where a configuration is loaded and again at the decision it protects.

- **Never raise in the `request` hook.** A raised hook forwards the flow, and a forwarded write
  escapes shadow mode. The decision fails closed as a whole (`decision-failed`), and the L0 echo
  never raises on any body.
- **THE SCOPE RULE.** No classification that forwards live may apply to an unsafe method it did
  not name explicitly. The loader refuses a live `default_kind`, a live kind on `*`, and a live
  kind on `DELETE`/`PUT`/`PATCH` without a `live_because:`; the classifier
  downgrades anything that reaches it anyway (`kind-downgraded`). `servicemap/rules.py` tells the
  story.
- **Stamping.** Every response irimi decided carries `Irimi-Answered-By` naming the answer;
  a live forward carries none, because absence is how a client tells the real service's response
  from ours. `tests/test_invariants.py` checks this against a real run and against policies
  built to break it. A control endpoint answer carries `control`, which is not an `answered_by`
  value because a control request is never an exchange (#73).
- **Irimi's own wire vocabulary is never the agent's.** The query pair irimi drops from a read it
  translates stays in the engine, which hands it back to the overlay with the response; it never
  goes on the wire. An agent-sent `Irimi-Rewrote` is stripped in the `request` hook all the same.
  `Irimi-Run` names the run a request belongs to; the `request` hook reads it and then
  strips it from the flow and the recorded request, so no live forward, answer target or L3
  read carries the agent's run id to a service, and `Exchange.run_id` is the one place it is
  kept (#67).
- **Targets stay on the machine.** A target must be loopback unless `--allow-target-host` says
  otherwise; a credential-path host (`hooks.slack.com`) has no such escape; irimi's own listener
  is never a target; credential headers are stripped unless the route opts in. `netaddr` is the
  one spelling of "loopback" all of these share.
- **Nothing reaches disk unredacted, and the live flow is never redacted.** The store redacts its
  own copy of each exchange with `redact.redact_exchange`; the engine and the agent's answer never
  see a placeholder. A part that cannot be redacted is stored as `<redaction-failed>`, never as it
  was (#69).
- **A recording failure never affects traffic** (design §5.2). No `TraceStore` method may raise
  or block: `DirectoryStore` only enqueues, and drops and counts what it cannot write. `ShadowSession.record`
  guards the call anyway, so a store that breaks the contract costs the exchange its record, never
  the hook, the terminal line or the summary (#70).
- **Telemetry is forwarded and its requests and responses are never stored.** One line per
  exchange records only that it happened and to which host, so a stored run's summary can count
  it. A trace of the agent's own observability traffic is noise, and replaying it would re-emit
  someone else's events (#70).
- **L0 is the floor.** A route with no `fixture:`, and a fixture this install cannot read, are
  both answered with the L0 echo rather than refused - the second carries `fixture-failed`, so
  the trace never claims a fidelity the answer did not have.
- **A delegated service gets no overlay, and a streamed response is never rewritten.** Both are
  written down at the top of `overlay.py` for Phase 2 to inherit.
- **A write L3 rejected never enters the write log, and shadow mode is never built without a
  reader.** The first keeps a write irimi says would have been refused from being replayed onto
  later reads as though it had happened; the second is what stops the whole L3 path from silently
  doing nothing in the product while every test that builds a policy bare still passes.
  `tests/test_invariants.py` holds both against a real run (#45).
- **A precondition says `not_evaluable` rather than guessing, in either direction.** A false
  rejection invents a refusal the service never made; a false pass claims a check that never ran,
  and the summary prints `L3 preconditions passed` off it. So a non-200, an unparseable body, an
  overlay that knows it is `partial`, and a document the check itself cannot read all record
  `not_evaluable` and fake the write at L2 (#45).
- **A read of an object this run minted is answered, not left as the service's refusal.** It is
  the one read the real service could not have answered: it has never heard of the id, so it
  refuses, and handing the agent that refusal for an object irimi told it exists is the
  contradiction the overlay exists to prevent. The read still goes out and still counts as a real
  read; the overlay replaces the body and, for Stripe's 404, the status. Only over the service's own
  not-found (`resource_missing`, `thread_not_found`): a rate limit or a bad key on the same read is
  left as sent and `partial`, because production would have sent it for the real object too. Every
  other effect leaves the status the service's. The alternative - answering such a read locally, off the write log,
  the way a faked write is - was weighed and refused, because it makes a read irimi never forwards
  (#52).
- **Only a write that would have happened lists its webhooks.** `would_fire` is set on the one
  path where irimi accepted and faked a write, so an L3 rejection, an idempotency conflict, a
  replay and a delegated write all list nothing by construction, not by a second check - the same
  set the write log holds. A replay listing its events again would promise one refund's
  `refund.created` twice. `tests/test_invariants.py` holds it against a real run (#47).

## State on disk

```
$IRIMI_HOME/            default ~/.irimi
  ca/ca.key             the local CA's private key (0600)
  ca/ca.pem             the CA certificate the child process is told to trust
  mitm/mitmproxy-ca.pem key + cert, the bundle mitmproxy mints leaf certificates from
  redact.key            the redaction HMAC key (0600), created on first use (#69)
  store/                the trace store, unless --store names another (#70):
    blobs/<sha256>        a redacted body, written once
    runs/<run_id>/        run.json and events.jsonl, one directory per run
    unattributed/         events.jsonl for events no usable run id claimed
    serve.lock            held by the one serve writing this store, while it runs (#77)
  maps.yaml             optional: the user's overrides file (targets only)
./irimi.maps.yaml       optional: a per-project overrides file; wins over the one above
```

No config file chooses the mode. The command is the mode. Under `irimi shadow -- <cmd>` one
process tree is one run, stored as the `process` run; the child learns the run id, 16 hex
characters, from `IRIMI_RUN`, and where the control endpoint is from `IRIMI_CONTROL` (#73). Under
`irimi shadow --serve`, and `irimi serve`, its alias, there is no child and no process run: the
engine's own run is `unattributed`, every run is one the SDK names on its requests, and the agent
is given `IRIMI_CONTROL` by whoever deploys it (#77).
